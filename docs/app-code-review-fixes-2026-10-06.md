# Code review and fixes — 6 October 2026

Reviewed the current working tree, including the existing uncommitted and untracked application changes. Scope covered startup and lifecycle, native and embedded playback, connectivity and recovery, channel/provider configuration, playlist and programme parsers, Room persistence, guide/favorites/settings/diagnostics navigation, shared UI components, Gradle configuration, CI workflows, and support scripts. Existing work was preserved; no commit, push, or deployment was performed.

Implemented 13 findings: two P1, ten P2, and one P3. P1 denotes a broken delivery path or important data-integrity defect; P2 denotes a functional or robustness defect; P3 denotes a smaller display defect. Dependency-update lint warnings were not treated as bugs or used to justify dependency upgrades.

## Practical limits

The TV regressions use local fixtures, deterministic Media3 state, and local HTML media on the available API 34 TV emulator. This review does not establish live broadcaster availability, account access, signed release delivery, long-session memory/frame-time measurements, or behavior on every physical TV.

The new database column defaults historical programmes to priority zero because their original source was not stored. Subsequent successful guide imports populate their actual priority. Higher-priority cached programmes remain protected until that source replaces them or expired records are pruned; this preserves guide data during source outages.
